# Створення планерів: контракт v2, 8 листопада 2026

Погоджено користувачем: підключити наявні налаштування ручних форм до створення через Неморі. Психологію, практичну користь, психологічний розбір і конкретні кроки не скорочувати. Нові ручні поля, редизайн і автоматичне редагування/скасування не входять у зміну.

## Реалізація

Основна модель отримує стислий перелік можливостей та правило уточнення обов’язкових/суперечливих параметрів. Luna отримує повний контракт полів. Сервер перевіряє весь масив; непідтримувані параметри не відкидаються мовчки. Фронтенд використовує чинні транзакції збереження й планувальники сповіщень.

| Планер | Параметри v2 |
|---|---|
| Завдання | Без дати або початок/кінець із часом; повтори, дні, завершення серії; одне сповіщення; форматований опис з інтерактивним списком |
| Подія | Початок/кінець, тривалість, повтори й завершення; кілька сповіщень; місце, важливість |
| Звичка | check/count/value, одиниці, мінімум/максимум включно з нулем, денна/тижнева норма, вибрані дні, часові вікна, завершення, часи/дні/відступ сповіщень |
| Ціль | Початок, дедлайн, упорядковані етапи з власними датами; сповіщення цілі та етапів |
| Нагадування | Опис, дата/час, повтори, дні та завершення серії |
| Чекліст | Повний дослівний упорядкований список, включно з повторюваними пунктами |
| Нотатка | Абзаци, виділення, звичайні списки, закріплення; лише вже дозволені аудіопосилання |

Колір/іконка підтримані для всіх типів; видимість — для типів, що вже мають її в ручній формі. Чеклісти/нотатки залишаються тільки в планерах. Глобальні налаштування видимості мають чинну пріоритетність. Приховані етапи завдань, довільні інтервали повторів, пріоритет завдань/нагадувань і категорія події не активуються.

`plannerCreationVersion:2` передається тільки новим клієнтом. Попередні клієнти зберігають контракт v1. V2-нагадування проходять одним шляхом `plannerCreations`, без дублювання в `scheduledReminders`. Повтор після помилки сповіщень відновлює розклад уже збереженого планера, не перезаписує його. Статистика створення надсилається після збереження незалежно від успіху ОС-сповіщення, через чинний best-effort/idempotent API. Це не гарантія доставки статистики офлайн.

Канонічна схема: `src/ai/utils/planner-creation-v2.ts`; копія фронтенду генерується `node scripts/sync-planner-contract.cjs`, перевірка — з `--check`. Виконавець: `diary-front/utils/nemory-actions/createPlannerV2.ts`. Аудіо дозволяються лише з успішної чинної підготовки медіа, окремо для користувача, сховища та джерела; довільні шляхи від моделі не приймаються.

## Що змінено в промптах

| Було | Стало |
|---|---|
| Основна модель знала загальний перелік і кілька обов’язкових полів | Компактний перелік реальних параметрів кожного типу; уточнювати необхідне/конфлікти, не перепитувати необов’язкові стандартні значення |
| Luna отримувала обмежену схему створення | Для v2 — повна схема вище, перевірка збереження всіх явних параметрів, єдиний шлях нагадувань |
| У action-only обробці коротке «так» могло втрачати попередню пропозицію | `previousAssistantText` входить у поточний обмін як контекст прийняття, без повторного виконання історії |
| `Only supplied history exists. Capsules/legacy=...` | `Supplied context only:...` — стислий технічний опис джерел, дат і походження |
| Розгорнуті технічні пояснення статусів/лічильників/дат | Та сама різниця мінімум/максимум, період/внесення, план/дія, джерело/висновок у компактному записі |
| `Use it unless explicitly requested otherwise...` | `Only explicit requests override within their scope` — збережена явна зміна мови та її область |
| `User name... Timezone... locale...` | `Name... timezone...` — мова вже задається мовним правилом і локалізованими назвами UI |
| `When executing creation append... otherwise omit` | `Creation only:append... else omit` — той самий службовий маркер |

Технічний опис посилань на зображення також ущільнений; обмеження, підтвердження та формат збережені. Роль психолога, доказовість, механізми, робота з історією, психологічне трактування планів, стиль, користь, практичні кроки та задачі відповіді захищені SHA-256-порівнянням із `f2bcd73`. Повні задачі розмов і підсумків не змінено. Контроль: `protected-prompts.json` і `planner-psychology-protection.spec.ts`.

## Бюджет основних інструкцій

`node scripts/measure-planner-prompt.cjs`: o200k_base, 216 комбінацій: 4 локалі × 9 режимів × задана/автоматична мова × 3 імені, найдовші значення компактних стилів, усі можливості, перший запис/чекін, Qwen-нагадування про мову та запас на UUID. Це інструкції контрольного профілю, не повний запит з історією, медіа й довільним профілем.

| Українська | Токени |
|---|---:|
| Запис | 2935 |
| Чекін | 2982 |
| Діалог запису | 2786 |
| Діалог чекіну | 2817 |
| Розмова | 2601 |
| День / тиждень / місяць / рік | 2754 / 2785 / 2757 / 2810 |

Таблиця: ім’я Олег, мова відповіді Ukrainian, UI uk. Найбільше у повній матриці — **2990**: UI uk, чекін, автоматична мова, Олександра-Марія. Для заданої мови/імені Олег максимуми EN 2940, PL 2973, DE 2962. Схема Luna рахується окремо, не приховується в цих числах. У реальних тестах фіксуємо основні інструкції, повний input, cached/fresh input, output і фактичні кредити повного циклу включно з Luna та іншими викликами за наявними діагностикою/білінгом.

## Межі приймання

Попередній етап до додаткового аудиту: 175 цільових тестів бекенду (схема 30, захист психології 8, загальний промпт 58, бюджет 21, gateway 32, розмови 17, інтеграція екстракції 9); 12 тестів нового фронтенд-виконавця. Окремо раніше пройшли 18 перевірок форматування/нотаток і 28 legacy creation/statistics. TypeScript обох проєктів, scoped ESLint нових backend-модулів, parity згенерованого контракту та звичайний `git diff --check` — PASS. Тести перевіряють код із підставними відповідями провайдера; живу якість генерації не доводять.

Автоматичні перевірки не замінюють якість відповіді моделі та перевірку встановленої збірки. Потрібні новий фронтенд і оновлений бекенд, далі погоджені R01–R10 без повторного розширення мапи. У цій роботі платних API-викликів: 0; витрат кредитів Nemory: 0. Фактичний облік токенів Codex недоступний.

Широкий старий `memory-capsule-v2.spec.ts` має 7 сторонніх невідповідностей чинному коду: відсутні старі приватні методи, застарілий текст дедуплікації та стара сигнатура pricing spy. Пов’язані з v2 сценарії перевіряються окремо; весь цей набір не оголошується зеленим.
