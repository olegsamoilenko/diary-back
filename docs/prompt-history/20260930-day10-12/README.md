# Пакет промптів після аудитів 10–12 — 30.09.2026

ID `20260930-day10-12`. Користувач дозволив п'ять корективів і окремо попросив можливість відкату при погіршенні відповідей.

## Архів

- `before/`: попередній код, відновлений з точних змін цього пакета у робочій копії. Це **не git HEAD і не побітовий знімок до редагування**; закінчення рядків нормалізовані до LF. Раніше погоджені зміни, включно з тарифними бюджетами дня, збережені.
- `after/`: код після пакета. Копії мають суфікс `.ts.txt`, щоб не потрапляти в TypeScript build.
- `forward.patch` / `rollback.patch`: прямий і зворотний патчі десяти файлів лише цього пакета, включно з тестами. Новий daily-capsule.spec.ts видаляється при відкаті.
- `manifest.json`: SHA256 нормалізованих версій та ознака існування кожного файла до змін.

## Зміст

1. Спільний живий REFLECTION_HYPOTHESES для записів, чекінів, діалогів і periodic tasks: змістовна відповідь без очікування уточнення; питання лише коли змінює розуміння/пораду. Причинний висновок позначається як гіпотеза без ритуальних застережень; попередня AI-версія не стає фактом, імпульс не тотожний дії, точкова метрика не описує весь день.
2. MEMORY_FACT_FIDELITY і SOURCE_CAPSULE_BLOCKS: збереження походження пояснення, початкового сприйняття/реакції/дії/корекції, першої спроби й невідомого результату. Переказ не приписує пораді вже раніше виконану дію.
3. Source extraction: конкретна довжина джерела, інструкція не розширювати короткий запис і стискати повтори. Durable selection також для сумісного старого extraction: problems стає vulnerability і підлягає тим самим критеріям. Невідомий майбутній результат або стан чекліста залишається у digest.
4. День: єдиний бюджет прози після резерву незмінних SOURCE_OBSERVATIONS. Відсоток повтору рахується від прози. При1402 total/389 fixed:511 target/611 max прози; скорочення50%. На повтор передається лише проза; точні спостереження додає застосунок. Якщо fixed block займає soft target, використовуємо залишок hard budget; при fixed>=1000 зберігається skip retry.
5. Діагностика зберігає обидві версії й додає reductionBasis, fixedEvidenceTokens, proseBudget та фактичне скорочення прози поруч із загальним. Один повтор і збереження першої завершеної капсули при невдалому повторі залишені.

Не змінено: моделі, ціни, тарифні контекстні ліміти8000/10000/12000, вихідні ліміти, API/storage, UI, пошук і виключення userMemory за sourceId вже включеної капсули. Наявні капсули не перегенеровані; збережені діалоги використовують свій frozen prompt.

## Перевірка

TypeScript і scoped ESLint пройшли. У п'яти наборах116 тестів пройшли,5 збоїв у старому memory-capsule-v2.spec.ts: відсутні раніше видалені buildDialogResponseDiscipline/buildUserMemoryNormalizationDiagnostics, старе дослівне очікування dedup prompt, стара арність recordAiUsage. Причини не внесені пакетом, звірені з before. Чотири набори daily capsule / periodic analysis / shared response prompt / source blocks пройшли повністю; нова перевірка live user-memory prompt теж пройшла.

Синтаксис обох версій, оборотність патча і `git apply --check --ignore-space-change` перевірені. Архів не містить нових сирих записів користувача. Платних модельних викликів і нового прогону сідів не було; якість відповіді ще не підтверджена.
