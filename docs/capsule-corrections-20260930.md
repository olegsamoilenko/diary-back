# Capsule correction batch — 30 September 2026

Implemented after the user approved the September 7–9 correction batch. Explicit constraint, clarified again during implementation: preserve the prohibition on invented patterns/causes. A hypothesis must connect supplied observations to established psychological or behavioral knowledge. Explain the mechanism, not just the event and advice; identify the personal interpretation as tentative and use dialog questions to support, revise or reject it. No hypothesis quota or obligatory disclaimer/question.

## Changes

- `journal-response-instructions.ts`, `response-system-prompt.ts`, `periodic-analysis.prompt.ts`: grounded, openly attributed hypotheses in entries, check-ins, dialogs and periodic tasks. Shared reasoning is situation → explanation of a possible mechanism → practical action, without mandatory headings. A named concept or the word "maybe" is insufficient: explain how observed details fit the mechanism. Focused dialog questions should distinguish explanations and may disconfirm the initial hypothesis. Invented dates/actions are still not evidence. Account for known deadlines and dependencies when proposing timing.
- `memory-fact-fidelity.ts`, `capsule-content-blocks.ts`, `ai.service.ts`: preserve useful explanations as attributed hypotheses, concrete nouns, chronology, corrections and dialog outcomes. A pending task alone is not a durable vulnerability. Dialog `assistantMemory` now includes the answer/explanation, not only long-term strategies; its existing schema and consumers remain intact.
- Source extraction receives an application-computed local timestamp, including seasonal offsets. Periodic snapshot copies render known epoch/ISO instant fields in local time before both main and Luna calls. Date-only plans and authored text remain untouched; source hashes still use the original DTO.
- Check-in extraction removes proven repeated question/answer data from structured context. Known rendered headers can omit duplicate measurements when those measurements are supplied separately. Daily notes, titles, extra notes, and unknown/older formats are retained.
- Daily capsule mood/metrics are appended by code in a compact `SOURCE_OBSERVATIONS` block, with each source ID and its own date/time. Repeated IDs count once; distinct entries remain distinct. The block is restored after either model pass, so a model omission cannot erase those supplied measurements. No new day-level measurements are generated.
- The complete capsule, including observations, still targets 900 tokens with an accepted maximum of 1000. Luna receives the remaining prose budget. One conditional retry now receives a percentage, absolute target and a character guide computed from the first text's measured density; it is asked to rewrite densely instead of cosmetically rephrase. Character guidance is not a truncation rule.
- A failed, invalid or oversized retry still preserves the complete first capsule. If fixed measurements alone fill the maximum budget, no paid retry is attempted. At most two capsule calls; no clipping. The first pass receives the same source payload as the main model plus its answer; the second receives only the first capsule.
- Existing console/file diagnostics keep both passes and actual token reduction. When fixed observations are appended, `generatedCapsule` additionally preserves exactly what Luna wrote and `capsule` shows the assembled text used downstream. Semantic preservation still requires review, not just a token-count check.
