# BUG-N6-06 — статус покупки кредитів після повернення

## 28.10 — поточне рішення: повідомлення Google, без опитування історії

Користувач підтвердив: під час повернення в Play Console прапорець «Відкликати доступ / Revoke» був, але його НЕ ввімкнули. Це відповідає refund без відкликання entitlement: Google документує відсутність revocation/voided повідомлення для refund без revoke. Розбіжність order REFUNDED / purchase CANCELLED / наш CONSUMED сама по собі не доводить збій доставки. Для перевірки автоматичного відкликання кредитів потрібен Refund + Revoke. Попередня версія документа з cron кожні10 хвилин скасована; старе N6-06.2 спостереження не є PASS тесту відкликання і не доводить PROD-дефект callback.

Новий cron reconcilePurchasedCreditRefunds, обходи50 покупок і записи refundCheckedAt видалені до деплою. Немає нового регулярного опитування Google. Чинний окремий retryPendingFinancialDetails стосується незавершених фінансових даних і цією правкою не змінюється.

Залишені локальні правки:
- ONE_TIME_PRODUCT_CANCELED (type2) перевіряє конкретну вже зараховану покупку через Google і застосовує чинну ідемпотентну refund-транзакцію лише для CANCELLED із відповідними productId/orderId. Мережевий timeout30с; помилка повертається до Pub/Sub, без локального циклу.
- VoidedPurchaseNotification productType2 використовує чинне відкликання. Відсутній гаманець відомої покупки тепер дає503 замість помилкового200, щоб Pub/Sub повторив подію.
- Серверні [IAP RTDN] received / credit-result / acknowledged / failed містять messageId, тип події та результат; без purchaseToken, payload чи сирих Google error objects. Невідома покупка логиться CREDIT_PURCHASE_NOT_FOUND; чинна поведінка підтвердження невідомих покупок збережена.
- Кінцевий статус, блокування purchase+wallet, один REFUND ledger та чинна політика боргу збережені. Новий білд фронтенду/міграція для цієї правки не потрібні. Деплоїть користувач.

**Локальна перевірка після вилучення опитування:**58 тестів PASS у5 цільових наборах; TypeScript --noEmit, scoped ESLint і diff-check PASS. Це автоматичні mock-перевірки, не production-приймання. Користувач підтвердив, що ще не деплоїв; нового cron на сервері не запускали.

### Необхідний ретест після деплою

- **N6-06.2a:** після справжнього Refund + Revoke перевірити RTDN received (voided або one-time type2), credit-result handled=true і acknowledged; у БД REFUNDED, creditsRevoked, refundedAt, один REFUND. Звірити баланс у застосунку. Старий refund без Revoke сам повторно не надсилається; не вимагати очікування cron чи нової покупки зараз. Подальша тестова покупка/дія повернення — за рішенням користувача.
- **N6-06.2b:** повторне відкриття не змінює баланс; повтор тієї самої події не створює другого REFUND. Повторна доставка й гонка двох повідомлень перевіряються автоматично; не додавати ручний дубльований сценарій.

Якщо до відкликання баланс19999 і відкликається20000, за відсутності інших змін balance=-1, доступний залишок0, debt1. Старе повернення без Revoke автоматично не коригується цією правкою; будь-яке окреме виправлення старої покупки потребує окремого рішення.

Документація Google: https://developer.android.com/google/play/billing/integrate#handle-rejected-or-unfulfilled-purchases ; https://developer.android.com/google/play/billing/rtdn-reference ; https://docs.cloud.google.com/pubsub/docs/push . Обидва варіанти налаштування RTDN включають voided purchases; режим усіх повідомлень додатково включає one-time type2.

Статус: локальна реалізація; N6-06.1 у виданому користувацькому сценарії пройдено 28.10.2026. Серверні внутрішні стани та production-деплой цим не підтверджені.

## Що змінено

`src/credits/credit-purchases.service.ts`: кінцеві статуси не проходять повторне споживання.
