# NA-35 — заборона писати поширюється на редагування

Статус: виправлено локально, деплой виконує користувач. Ручний NA35.1 DEFERRED до завершення всіх NA-корекцій. Автотести не означають USER PASS.

## Погоджена поведінка

За рішенням користувача 29.10 активне обмеження публікації блокує створення й редагування власних тем/коментарів. Видалення власного залишається дозволеним щодо цього обмеження; перевірки авторства, стану контенту й блокування теми не змінюються.

`ForumTopicsService.updateTopic` і `ForumCommentsService.updateComment` використовують наявну `ForumUserRestrictionsService.assertCanWrite` після перевірок контенту/авторства, до `publication.moderate` і запису. Збережено чинну помилку 403 / `YOUR_COMMUNITY_POSTING_IS_RESTRICTED`, яку вже повертає створення. Чинний запит враховує is_active, lifted_at, starts_at, ends_at; після зняття/закінчення обмеження воно перестає блокувати наступний запит без повторного входу.

NA-47 lifecycle збережено: відхилення restriction не витрачає Redis admission/rate слот та AI-модерацію. Нових маршрутів/залежностей/міграцій/env немає, фронтовий rebuild для NA-35 не потрібен.

## Автоперевірки

29.10: 42 тести / 2 suites PASS, включно з 14 новими перевірками NA-35; повний TypeScript, scoped ESLint і diff-check PASS. Перевірки на телефоні та деплой ще не виконані.

Розширено `forum-publication-consumers.spec.ts`: усі чотири write methods з реальним restrictions service та ізольованим repository. Активне обмеження → 403 без admission/moderation/DB-write/Telegram; зняття → негайний успішний повтор; перевірено часові та lifted predicates SQL query builder. Чужі теми/коментарі не редагуються. `deleteTopic`, `softDeleteComment`, `deleteComment` дозволяють власне видалення при restriction, але відхиляють чужого автора. Репозиторії ізольовані mock-об'єктами; реальних публікацій, admin restrictions, AI/Telegram/push немає.

Додатково збережені регресійні сценарії NA-47: rollback, commit, помилки до/після commit, policy rejection. Ручна гонка/штучні відмови для NA-35 не потрібні.

## NA35.1 — один необхідний ручний сценарій, DEFERRED

На тестовому акаунті з власною темою та двома коментарями:

1. Через адмінку ввімкнути заборону писати. Спробувати змінити тему й один коментар: жодна зміна не зберігається, застосунок показує обмеження.
2. Видалити другий власний коментар: видалення доступне й після оновлення підтверджене.
3. Зняти заборону в адмінці; повторити редагування теми й коментаря: збереження успішне без повторного входу. Нову публікацію поєднати зі звичайним сценарієм спільноти.

Проходити на DEV фронті з виправленим DEV беком після всіх корекцій; на PROD повторити у спільному сценарії спільноти лише якщо не перевіряли цей сценарій на DEV. Не накладати обмеження на реальних користувачів для тесту.

## Межі

Правило приватних DM із додаткового уточнення аудиту NA-35 не змінено: чинний frontend consumer не підтверджений, поширення posting restriction на DM потребує окремого продуктового рішення. Цей пункт не позначено закритим. Правка також не обіцяє скасування операції, що вже пройшла перевірку перед одночасним накладанням обмеження.
