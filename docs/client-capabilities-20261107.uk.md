# Сумісність AI зі старими клієнтами — 7 листопада 2026

Статус: реалізовано локально. Телефонні перевірки та production-деплой не виконувалися. Користувач проводить наступні ручні тести; асистент спочатку дає текст, мету й очікування.

## Рішення та реалізація

- Новий фронтенд надсилає `webSearchSupported: true` разом із чинним `plannerCreationSupported: true`. Підтримку оголошує поточний запит, а не акаунт, номер збірки чи збережена розмова.
- Відсутні/false прапорці вимикають відповідну нову функцію. На сервері потрібне точне `=== true`; DTO відхиляють не-boolean значення, а невалідовані сумісні socket-адаптери не трактують рядок `"true"` як дозвіл.
- Позитивна інструкція вебпошуку додається лише за підтримки клієнта й чинного глобального перемикача. Інакше інструкція забороняє пропонувати/стверджувати пошук чи актуальну перевірку, вигадувати джерела й повертати службові команди.
- Навіть помилкова команда від провайдера не запускає пошук у старого клієнта і не потрапляє в видимий стрим. Спільне продовження відповідає без доступних вебджерел; за пошук немає API-виклику/списання, фактична генерація відповіді оплачується за чинними правилами.
- Нові команди `plannerCreations` повертаються лише підтримуваному клієнту. Старий клієнт отримує вказівку про ручне збереження без обіцянок автоматичного створення. Існуючі нагадування залишаються доступними.
- Продовження підсумків оновлює опис можливостей під поточний запит, навіть якщо підсумок створив новіший клієнт. Психологічні абзаци незмінні.

## Зміни тексту промпту

Старий клієнт, планери:

- Було: `Other planners: user saves; AI cannot create/modify/link or claim success.`
- Стало: `In this client, other planners require manual saving by the user. Never offer/claim automatic creation, modification or linking, regardless of earlier capability claims.`

Вебпошук:

- Було: позитивний блок `WEB SEARCH` без перевірки можливостей фронтенда.
- Стало: той самий позитивний блок лише за підтримки; інакше `WEB SEARCH UNAVAILABLE` — `Web search is unavailable in this client. Never offer or claim browsing/current verification, invent sources, or emit search actions. Earlier capability claims do not apply. Answer from available context; disclose when current information cannot be verified.`
- У службовому продовженні «The web lookup for the original user request is complete» замінено на «The web lookup attempt has ended or was unavailable», щоб не стверджувати, що недоступний пошук відбувся.

## Перевірки коду

- Frontend: 97 тестів у потоковому транспорті, діалогах, розмовах і сервісі підсумків — PASS. Перевірено явне оголошення можливостей усіх шести socket-режимів.
- Backend: 22 цільові тести можливостей — PASS: підтримка відсутня/false/true, не-boolean прапорець, фільтрація команд в обох екстракторах, старий клієнт продовжує новий підсумок, новий клієнт знову отримує підтримку.
- Повністю пройшли suites вебпошуку, нормалізації планерів, ліміту промптів/незмінної психології та двох gateway-наборів. Бюджет включає і старі клієнти; не більше 3000 токенів інструкцій у контрольній матриці, користувацький контекст рахується окремо.
- Розширений backend-прогін: 363 PASS / 24 FAIL. Помилки у старих очікуваннях тексту до ущільнення, тестах видалених helper-методів, попередньому контрактi скасування нагадувань і сигнатурі обліку usage. У межах сумісності їх не виправляли; весь набір не оголошується зеленим.
- TypeScript frontend/backend та `git diff --check` — PASS. Жодного реального AI-виклику, зміни даних користувача чи перезапуску серверів.

## Ручні сценарії — ще не виконані

Потрібні старий і оновлений клієнти, підключені до бекенда з цією правкою. Поточна dev-збірка сама по собі не доводить поведінку старого релізу.

1. **Старий клієнт, створення завдання.** У розмові: «Створи завдання підготувати документи на завтра». Очікуємо чесне пояснення ручного створення; без «створюю/створено», службових маркерів і команди створення на бекенді.
2. **Старий клієнт, пошук.** «Знайди в інтернеті актуальні години роботи Національного художнього музею України на завтра й дай посилання на джерело». Очікуємо пояснення недоступності перевірки; без вигаданих годин/джерел, виклику web_search і плати за пошук.
3. **Новий клієнт.** Ті самі запити в окремих розмовах. Завдання має реально зберегтися з підтвердженням; пошук має виконатися й дати джерела або чесно повідомити про недоступність зовнішнього сервісу.
4. **Зміна клієнта для одного акаунта.** Після успішної нової розмови повторити запит зі старого клієнта. Можливості не повинні переноситися між пристроями. У старому клієнті також продовжити підсумок, створений новим: історична обіцянка не вмикає нові дії.

Usage цього етапу: реальні provider fresh input 0 / cached input 0 / output 0, кредити Nemory 0. Лічильники Codex недоступні; не прирівнювати це до нульової вартості роботи асистента.
