## Execution and evidence rules

- Test each common block in one suitable flow; mode-specific cases remain separate.
- Create only clearly marked synthetic test content. Do not delete or alter real
  journal entries, change billing balances, or publish community posts.
- Never seed reported outcomes as facts merely to make a model pass. Coverage
  gaps and unavailable summary periods must remain explicit blockers.
- Static checks: exact psychological preservation, schemas, runtime capability
  branching for images, current/legacy saved-report compatibility, full instruction
  budgets for all modes, language reminder and token diagnostics.
- Live quality is assessed by observed output and resulting app state. Static
  checks do not establish model quality, and a model's self-report is not proof.
- Record failures before fixes and repeat the failing scenario after correction.
- Record Nemory fresh/cache-read/cache-write/output tokens and credits separately
  from unavailable Codex usage. Do not claim deployment or all-mode acceptance
  until the corresponding evidence exists.
