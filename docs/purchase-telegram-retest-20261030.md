## Поведінка

- За рішенням користувача поновлення за замовчуванням не надсилаються. Спільний обробник immediate/cron розпізнає Google renewal за суфіксом номера замовлення `..0`, `..1`, … ([формат Google](https://support.google.com/googleplay/android-developer/answer/6135870)). Не визначаємо поновлення за наявністю інших покупок користувача. При вимкненому прапорці повідомлення отримує `skipped`, без зміни оплати/тарифу; увімкнення пізніше не розсилає вже пропущену історію. Стан, надісланий до зміни прапорця, не відкликається.

- Нові рядки отримують `pending` у чинній транзакції покупки. Повторне підтвердження/RTDN/upsert не скидає маркер. Історичні рядки мають NULL та не розсилаються. Нові покупки, зареєстровані після встановлення цього коду при вимкненій доставці, залишаються в черзі до її ввімкнення.
- Перша спроба надсилання запускається у фоні одразу після commit нарахування кредитів або збереження `PROCESSED` чинною фінансовою синхронізацією підписки. Покупка не очікує відповіді Telegram. Cron раз на хвилину читає **локальну БД** як резервний механізм, без нових запитів до Google. Обидва шляхи використовують один SQL claim. Кредити — лише `PURCHASED/CONSUMED`, ненульове нарахування без відкликаних кредитів. Новий оплачений період має окреме замовлення і повідомлення. Тестові покупки позначені.
- Статус `sending` і точний timestamp захищають від конкурентних обробників. До 20 рядків кожного типу за цикл; залишок продовжується наступним циклом. Транспорт Telegram до 30 с; помилка не змінює платіж/тариф/гаманець і не блокує відповідь покупки. Повтор або відновлення після падіння — через 5 хвилин.
- Штучного очікування наступного хвилинного циклу для першої спроби немає. Для підписок зберігається очікування фінансового підтвердження Google; його чинний розклад не змінено. Час фактичного отримання також залежить від Telegram і мережі. Для кредитів невідома сума підписана «ще уточнюється», без вигадування ціни й нового повідомлення лише заради уточнення суми.
- Повторні перевірки покупки не створюють дубля. **Межа гарантії:** Telegram sendMessage не має ключа ідемпотентності. Якщо Telegram прийняв повідомлення, а відповідь загубилася або запис `sent` не зберігся, повтор доставки може створити дубль. Для звіряння є стабільний ID події. Exactly-once не заявляється.
- Повідомлення: ім’я/ID користувача, модель/ОС/версія та build застосунку, продукт/тариф або кількість кредитів, сума/валюта за наявності, order ID. Пристрій явно підписаний як **останні збережені дані акаунта**, не гарантовано телефон самої покупки. Немає email, purchase token, device unique ID, raw payload чи приватних записів; plain text, обмежені поля. Вхідні повідомлення бот не обробляє й не пересилає.
