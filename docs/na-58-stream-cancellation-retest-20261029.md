# NA-58 — відключення під час AI-відповіді

Статус: виправлено локально, автоматичні перевірки пройдено. Деплой виконує користувач; ручний тест відкладено до завершення всіх погоджених корекцій.

## Погоджене виправлення

`stream_ai_comment`, `stream_ai_checkin` і пов'язаний `stream_ai_dialog` передають сигнал відключення у чинний `generateComment → executeResponse` lifecycle. Спільний механізм реєстрації/видалення disconnect-listener використовується також розмовами та періодичними аналізами. Застарілий callback більше не кидає окрему помилку, яка обходила облік.

При відключенні SDK отримує AbortSignal. Спільний AI-сервіс обліковує фактичне usage провайдера; без нього оцінка допускається лише за наявності тексту відповіді. Після обліку скасування перериває завершення: немає `done`, запису завершеної відповіді в моніторинг чи подальшої обробки результату. Відключений до початку запит не запускає provider; раннє відключення без тексту та без provider usage не списується. Нова сесія має незалежний сигнал.

Формули, ціни, payload/event names, правила збереження запису на фронті та облік уже виконаних підготовчих медіаоперацій не змінюються. Сигнал — необов'язковий останній аргумент внутрішнього `generateComment`, тому чинні HTTP/інші виклики без нього залишаються сумісними. Нових таймерів, лімітів або перезапуску запитів немає.

Скасування залежить від того, коли сервер виявить розрив Socket.IO: миттєва втрата мережі на телефоні не завжди одразу стає `disconnect` на сервері. Якщо остаточне usage не отримано, оцінка не гарантує точного збігу з остаточним рахунком провайдера. Звичайні provider/billing failures не перетворюються на успішну відповідь.

## Автоматичні перевірки

29.10.2026: **106 тестів / 8 suites PASS**, включно з 24 новими сценаріями `entry-stream-cancellation.spec.ts`. Після першого запуску виправлено застарілі очікування у двох суміжних suites та повторено лише їх: три чинні image flags у periodic dialog; транзакційний manager legacy-списання після NA-34; чинний image timeout 600000. Production timeout і формули цією правкою не змінювались. `tsc --noEmit` та `git diff --check` PASS. Scoped ESLint gateway/нових тестів PASS; змінені ділянки ai.service без lint diagnostics, поза ними залишаються 20 попередніх зауважень. Повний lint репозиторію не оголошено пройденим.

Реальні gateway, generateComment та provider/usage lifecycle, із підміненими SDK, обліком і сховищами: partial/plain/structured для запису й чекіну; діалоги обох типів; до першого тексту з/без actual usage; отримане actual/cached usage; нормальне завершення; звичайна помилка провайдера; відключений клієнт до початку; відключення під час підготовки; повторний запит після відключення; підтримувані provider adapters. Окремо чинні тести розмов/періодичних аналізів та обліку.

## Мінімальна ручна перевірка після всіх корекцій

**NA58.1 — DEFERRED / DEV з оновленим бекендом.** Поєднати з уже запланованим AI/мережевим сценарієм: запустити відповідь на запис або чекін, після першого тексту вимкнути інтернет. Після серверного визначення розриву перевірити скасування та одноразовий облік виконаної частини; незавершена відповідь не має прийти як `done`. Повернути інтернет і виконати наступну звичайну AI-дію — новий запит працює. Не вимагати точного збігу оцінених токенів із provider billing і не створювати додаткову платну генерацію, якщо цей сценарій уже включено в спільну перевірку. Другий тип запису та точні моменти розриву покривають автоматичні тести.

Для production зарахувати той самий сценарій у чинному чеклісті після деплою, без повторення всіх комбінацій. Міграції, нові env та rebuild фронту не потрібні. Автоматичні перевірки не викликають справжній provider і не змінюють користувацькі дані.
