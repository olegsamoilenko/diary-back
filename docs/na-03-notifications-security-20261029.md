# NA-03 — повідомлення та HTML в адмінці

2026-10-29: локально виправлено, деплой виконує користувач.

## Зміни

- `GET/POST /common-notifications`, `GET/POST /release-notifications` і `DELETE .../:id` вимагають чинну адміністративну сесію (`admin-jwt`). Звичайний JWT застосунку не підходить.
- Користувацькі `latest`, `mark-as-read`, `skip-this-version` залишаються під `jwt`, з попередніми маршрутами, форматами відповідей і прив'язкою до ID користувача.
- `notification-html.ts` очищує HTML до запису перекладів. Читання адміністративних списків і мобільних повідомлень також очищує старі дані, без масового переписування БД.
- В адмінці є одна спільна функція `lib/notificationHtml.ts` для редактора (початковий HTML, setHtml, get) та обох таблиць повідомлень. Політика відповідає backend; обидва незалежно розгортаються, узгодженість перевіряється тестами.
- Дозволено чинне форматування: заголовки H1–H3, абзаци, переноси, жирний, курсив, підкреслення, закреслення, HEX/RGB/RGBA кольори, чотири варіанти вирівнювання, списки, цитати, код, розділювачі, HTTP(S) зображення та HTTP(S)/mailto посилання. Збережено початковий номер списку та структуру Tiptap task-list. Checkbox у відображенні лише неактивний.
- Заборонено script/event handlers, iframe, SVG, активні форми, небезпечні URL-схеми та сторонні CSS-властивості. HTML-посилання мають `noopener noreferrer`.
- `docJson`, локалі, номери збірок, платформа, терміновість і правила показу залишилися. `docJson` не вставляється в DOM як HTML; перед використанням новим майбутнім споживачем необхідно зберегти цю межу довіри.
- API-функції видалення в адмінці тепер повертають failure на HTTP-відмову; діалог показує помилку та не викликає success callback. Успішне видалення закриває діалог і оновлює список.

## Перевірено

- **20/20 backend PASS:** реальні controllers, JWT strategies, ValidationPipe і services; синтетичні repositories/transaction. Anonymous і user не читають admin list та не створюють/видаляють; неактивний admin відхиляється; активний admin створює обидва переклади й видаляє потрібний ID. Перевірено збереження очищеного HTML, читання старих рядків, пагінацію та user latest/read/skip.
- **11/11 landing PASS:** узгодженість очищення та повторного очищення, форматування, шість небезпечних HTML-прикладів; SSR справжніх двох таблиць для EN/UK із перевіркою DOM-структури; чинні delete API wrappers із cookie transport та відмовою сервера.
- TypeScript обох репозиторіїв, ESLint змінених TS/TSX та `git diff --check` — PASS.
- Без реальних повідомлень, записів у БД, push, звернень до production чи виконання небезпечних дій у браузері. Це автоматизована перевірка контракту й розмітки, не ручне візуальне приймання адмінки.

## Деплой та коротка майбутня перевірка

Оновити **diary-back і diary-landing**. На бекенді додано `sanitize-html` 2.17.0 і типи: встановити залежності з оновленого lock-файлу перед збіркою. Міграції БД та новий мобільний білд не потрібні. Backend-захист працює і зі старою адмінкою; frontend-захист додатково очищує дані перед показом.

За рішенням користувача зараз не додаємо ручну матрицю адмінки. Під час її наступної перевірки достатньо одного сценарію **NA03.1**: створити тестове оголошення з двома мовами, заголовком, кольором, вирівнюванням, списком і посиланням; перевірити таблицю та показ у застосунку; видалити тестове оголошення. Не створювати такі повідомлення для реальних користувачів без окремого дозволу.
